# Security policy

## Supported versions

The current `0.x` source line is maintained on a best-effort basis while the project remains pre-release.

## Reporting a vulnerability

After the public GitHub repository is created, use that repository's private security advisory feature. Do not disclose sensitive reproduction steps in a public issue first.

Before repository creation, do not publish vulnerability details in this source workspace. Contact the project maintainer through the channel agreed for the future repository.

## Relevant security areas

Reports are especially useful for:

- path traversal or unsafe artifact output;
- private provider loading or isolation bypass;
- leaked local configuration, credentials, or generated artifacts;
- unsafe asset/resource handling;
- dependency vulnerabilities with a concrete project impact.
